# TC-PAGING/CACHE — pagination và Room

**PROPOSED / A4.** Baseline TECH-03 §2.1: stable order +ID tie-breaker, owner/filter-bound cursor, capped limit; TECH-02 §8 và TECH-03 §4.3: Room read cache, không auto outbox, owner isolation/foreground refresh. Các giá trị và snapshot semantics dưới đây chưa approved.

## Conversation/history pagination

- Sort membership/order snapshot: updated_at DESC, id DESC tại request page1. Filter gồm owner từ session, context kind, item ID nếu có, lifecycle và search query chuẩn hóa. Không gọi loaded-count là total.
- Đề xuất snapshot ID-list trong Redis hỗ trợ tạm thời, TTL15 phút; không long-running DB transaction. Freeze ordered IDs +sort key +filter hash +owner +created/expiry. PostgreSQL vẫn nguồn record/quyền hiện hành; snapshot không là business truth. Redis unavailable→503 LIST_SNAPSHOT_UNAVAILABLE; snapshot bị evict/hết hạn→400 CURSOR_EXPIRED, client reset page1. Không fallback offset âm thầm.
- Cursor opaque, signed/authenticated, chứa snapshot ref/index và filter/owner binding; client không chế tạo hoặc đổi filter dưới cursor cũ. Default limit20, max100; limit đổi không đổi snapshot order. Invalid signature/owner/filter→400 CURSOR_INVALID, không leak data.
- Mỗi page lấy next slice of frozen IDs, re-authorize/current lifecycle trước trả nội dung. Deleted/khác owner bị bỏ, không lộ title. Rows có thể cập nhật nội dung/version mới nhưng `sort_updated_at_snapshot` giữ vị trí snapshot; client không tự sort lại từng page. New/updated membership xuất hiện khi refresh page1.
- Khi skip deleted rows, page có thể ít hơn limit hoặc rỗng nhưng has_more vẫn true nếu snapshot còn IDs. next_cursor dựa index đã tiêu thụ, không dựa length response. Không lặp cursor. UI tiếp tục tải theo cursor hoặc user refresh, không giả account empty từ một empty page.
- `total_snapshot` chỉ trả nếu backend tính count chính xác theo snapshot, không total hiện hành; khi có visibility/lifecycle changes thì omit count hoặc báo count_as_of rõ. UI không cần total để hoạt động. Never infer from page length.
- Đề xuất resource bound: tối đa3 snapshots/user, TTL15 phút, tối đa1MiB metadata/snapshot; khi vượt trả503 SNAPSHOT_LIMIT với hướng dẫn thu hẹp query/retry. Không silently truncate hoặc mất history; tune sau load test và giữ contract revision. Đây là giới hạn vận hành cần Backend review, không user feature limit đã duyệt.

## Message và official history pagination

Messages có server sequence_no unique, được cấp trong transaction. Default page gần nhất50, max100, API trả data theo sequence ASC để render; cursor tải older theo before_sequence và snapshot upper sequence tại page1. Append sau upper bound nằm ngoài snapshot; thread refresh lấy latest và merge stable IDs. Delete thread invalidates mọi cursor/read. Sequence gap do redaction không được hiểu là thiếu record để bịa message.

Official evaluations/DecisionRecords query theo owner+item, order created_at DESC,id DESC, cursor bound item/filter. Không join vào conversation còn sống. Delete chat không invalidates quyền item history. Concurrent new evaluations xuất hiện khi refresh, không overwrite records cũ.

## Client query generations

Mỗi owner+query+filter+sort+snapshot có generation riêng. Search/filter/refresh/account switch tăng generation và reset cursors; response cũ không được merge vào generation mới. Upsert theo server resource ID; preserve scroll/anchor khi tải older. Cursor expired/invalid→clear page cursor và tải page1, không tự submit operation. Stale response không xóa record được source mới xác nhận.

## Room cache và pending journal

| Dữ liệu | Chính sách proposed |
|---|---|
| Conversation/messages/evaluation cache dùng trong Chat | Owner+server ID+server version+fetched_at, display TTL24h; stale label, không tự gia hạn TTL từ đọc cache |
| Capacity | Tối đa200 threads, tổng10.000 messages hoặc20MiB chat cache, đạt ngưỡng nào trước thì LRU eviction. Đây là local-cache bound, không xóa server history |
| Official history cache trong Item Detail | Theo item-domain policy; chat deletion không purge records chính thức, chỉ link transcript/cache chat |
| Unsent chat draft | Session/view state theo owner+thread/context, rotation giữ state; không hứa durable raw draft qua process death hoặc cloud. Back/context switch giữ riêng trong session, delete/logout xóa |
| Pending operation journal | Persist ID/key/payload hash/context/version/deadline/status tối thiểu trong private owner-scoped storage khi user đã gửi; không raw chat draft và không worker/outbox tự gửi |
| Existing Offline Manual Item Draft | Giữ baseline TECH-02/ADR-09 và ảnh bền vững; không dùng policy chat draft để làm mất item draft |
| Logout/account switch | Cancel subscriptions; clear rendered state và chat cache/draft/journal của account cũ khỏi active session; logout purge chat cache/journal. Item manual-draft behavior vẫn theo domain đã duyệt, không tự thay đổi |

Với process death, operation journal giúp lookup trước resend; nếu raw payload không còn thì không đoán hoặc tự tạo lại nội dung. Operation NOT_FOUND chưa đủ để gửi key mới; theo03. Journal không có background job auto submit. Dữ liệu nhạy cảm không log; token không nằm Room. Cơ chế mã hóa/storage cụ thể theo security capability repo, không tuyên bố Room tự mã hóa.

Local TTL check thực hiện trước render và khi app hoạt động; hệ điều hành có thể chưa chạy purge khi app đóng, nên không hứa bytes biến mất vật lý ngay đúng giờ trên máy tắt. Online remote deletion validation purge ngay khi được xác nhận. Backup/cache account isolation tests phải chạy sau implementation; policy không thay server authority.

## Failure behavior

Offline/no cache hoặc TTL expired→giải thích cần kết nối để tải, không “chưa từng có chat”. Network error giữ cache hợp lệ, không báo snapshot page đã complete. Cache migration có thể dựng lại chat read cache nhưng không làm mất pending identity trước reconcile và không phá Offline Manual Item Draft. Storage failure phải hiện giới hạn draft/recovery phù hợp, không báo send thành công cục bộ.

Tests IT12–IT15/IT17; thông số phía server và client chỉ effective khi A4 được approve và công bố qua contract/config revision.
